# تقرير الأمان — مورد v1.0.0

> SRS 20 بند 26 و16.5. الخلاصة: **لا ثغرة حرجة أو عالية الخطورة معروفة وغير معالجة**. كل بند أدناه مختبر آلياً أو موثّق بمكانه في الكود.
> تاريخ المراجعة: 2026-11-23.

## 1. نموذج الثقة

- **العميل غير موثوق.** التطبيق والموقع يعرضان ويرسلان فقط. لا كتابة من أي عميل إلى Firestore (`allow write: if false` لكل المسارات، ومختبر حتى للمالك: `firebase/test/rules.test.ts:78`).
- **الخادم وحده يكتب.** كل كتابة تمر بالـWorker: هوية ← صلاحية ← نطاق المحل ← تحقق المدخلات ← معاملة ذرية ← سجل تدقيق.
- **الصلاحيات تُحسب على الخادم** من الأدوار المخزنة + منح − حجب، وتُقرأ مع كل طلب (كاش 15 ثانية يُبطل فور أي تعديل). ما يرسله الهاتف من أدوار أو صلاحيات يُتجاهل (`srs-permissions.test.ts:62`).
- **المال يُحسب على الخادم:** أعداد صحيحة بالأغورة، إعادة حساب كل إجمالي، دفتر لا يُحذف منه، والتصحيح بقيد عكسي.

## 4. مخاطر متبقية مقبولة (موثقة لا مخفية)

| البند | التقييم | السبب |
|---|---|---|
| صور المنتجات عامة (`/files/products/*`) | منخفض | صور كتالوج بلا بيانات شخصية؛ عامة عمداً لتخزين CDN طويل وسرعة على النت الضعيف |

## 5. عند أي تغيير مستقبلي

مسار جديد ← `requirePerm` + نطاق المحل + اختبار رفض في `worker/test`. كتابة مالية ← معاملة + `auditWrite` + مفتاح تكرار. صلاحية جديدة ← `spec/permissions.json` واختبار spec. لا ترفع إصداراً قبل `npm audit` نظيف وكل الاختبارات خضراء.
